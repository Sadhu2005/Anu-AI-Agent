## Goal

The running production service itself autonomously discovers and executes a
real agent task, end to end:

```text
systemd → runtime → guardian → scheduler → agent → task → Safe Mutation
→ checkpoint → test → commit / rollback → DB
```

## Completed

### 1. Real production launcher identified

```text
anu-agent.service → /srv/anu/bin/anu-runtime.py
```

No separate scheduler daemon or timer is needed; the scheduler is embedded in
the runtime.

### 2. Scheduler embedded in the production runtime

`bin/anu-runtime.py` now runs, every 60 s:

```text
Guardian health check → resource admission → scheduler tick
```

The scheduler runs **only when Guardian status is `NORMAL`**, so resource
governance sits above autonomous execution. Each tick:

- `SCHEDULER_MAX_TASKS = 1`
- lock file `runtime/anu-scheduler.lock`
- database `brain/anu-brain.db`
- non-NORMAL → logs `Scheduler skipped: resource status=…` and returns `SKIPPED_RESOURCE`
- exceptions are logged (`Scheduler cycle failed: …`) and never crash the runtime

### 3. Resource safety is real

Admission policy (`config/anu-admission-policy.yaml`): min free RAM 2048 MB,
min free disk 50 GB, warning 60 °C, pause 65 °C, ANU RAM 3072 MB, CPU 50 %,
1 parallel task, workspace 30 GB, project 15 GB. The Pi stays well inside
these (≈46 °C, ≈7.3 GB free RAM, ≈437 GB free disk).

### 4. Checkpoint directory writable under systemd

systemd namespace restrictions would block checkpoint writes.
`/srv/anu/checkpoints` was added to the service's writable paths, and a
namespace probe confirmed the agent can write there.

### 5. Goal ID compatibility

SQLite stores integer `goal_id`; `AgentGoal` requires a string.
`bin/anu-agent-task-adapter-v0.1.py`:

```python
if isinstance(goal_id, int) and not isinstance(goal_id, bool):
    goal_id = str(goal_id)
```

Evidence: before the fix every runtime cycle logged
`ValueError: task cannot become AgentGoal: goal_id is missing`; after restart
(2026-10-04 17:43 UTC) the first cycle completed with `results=1`.

## Open Problem: Relative changes-file path

Task 186 ended `status = blocked`, `attempts = 1`, with **no** transaction ID,
checkpoint, or mutation event.

Cause: the service runs with working directory `/srv/anu/home`, and Safe
Mutation did `load_changes(args.changes_file)`, so the relative path was
resolved against the process directory instead of the project.

Fix (`bin/anu-safe-mutation-v0.2.py`):

```python
project = resolve_project(args.project)
changes_path = resolve_file(project, args.changes_file)
changes = load_changes(changes_path)
```

which resolves to
`/srv/anu/workspace/projects/sandbox-test-project/.anu-v0.5.9-changes.json`.
The regression test passed. The final integrity gate was deliberately not run yet.

## Policy Consistency Fix

### Why it happened

The Task Engine was implemented with a conservative hard-coded limit
(`MAX_ATTEMPTS = 3`) before the higher-level policy file was consolidated.
Resource files were likewise written at different stages, so three files
described the same limits differently, and two of them are read by different
components:

| Setting | Before | Read by | Problem |
|---|---|---|---|
| Max retries | `anu-policy.yaml`: 5 retries | nothing | Engine really allows 3 attempts; policy was misleading |
| Temperature | Guardian file: warn 65 / pause 70 °C; admission: 60 / 65 °C; policy: 70 °C | Guardian vs Governor | Scheduler gate and workload admission used different limits |
| Free disk | Guardian 20 GB vs admission 50 GB | Guardian vs Governor | Same |
| Checkpoints | missing from `anu-policy.yaml` writable list | — | systemd unit allowed it (V0.5.9), policy did not say so |
| Docker | `docker.enabled: false` | — | Read as "no Docker at all", but tests run in Docker via `anu-sandboxd` |

### Decision (best for the Raspberry Pi 5)

- **3 attempts per task.** Each attempt costs a checkpoint, a mutation and a
  sandbox run (≤ 512 MB, ≤ 120 s); a retry needs a new plan, so more identical
  attempts waste compute. Smarter "retry later" belongs to V0.6.0. Policy key
  renamed to `max_attempts_per_task: 3` to say exactly what the engine counts.
  No code change; `test_retry_exhaustion_v0_5_2.py` still asserts 3.
- **Warning 60 °C, pause 65 °C, resume 55 °C, 50 GB free disk** everywhere,
  matching the admission policy. Pi 5 throttles around 80 °C, so this keeps a
  large margin and protects the other production services on the Pi.
- **`/srv/anu/checkpoints`** added to the policy's writable paths.
- **Docker** clarified: ANU has no direct Docker access; sandboxed execution
  goes only through the root `anu-sandboxd`.

### Verified

Guardian `determine_status()` run on the Pi against the new config:
46 °C → NORMAL, 59.9 °C → NORMAL, 60 °C → WARNING, 64.9 °C → WARNING,
65 °C → PAUSE, 49 GB free disk → PAUSE. All three YAML files parse.

### Effect on the live Pi

Not deployed yet. On the Pi the Guardian still uses 65 / 70 °C and 20 GB
until the config is deployed with the V0.5.9 freeze. Because the scheduler only
runs on `NORMAL`, new work will then stop at 60 °C instead of 65 °C.
