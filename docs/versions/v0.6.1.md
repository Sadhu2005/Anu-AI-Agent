## Goal

This is where ANU becomes genuinely agentic. Move from `Task → Execute` to:

```text
GOAL → PLAN → TASK GRAPH → TASK 1 → TASK 2 → TASK 3
```

## Example

```text
Goal: Improve sandbox project
Plan:
 ├── inspect project
 ├── identify issue
 ├── propose modification
 ├── test modification
 ├── apply modification
 └── verify final state
```

## Scope

- Goal record (`goals` table) as the top-level unit of work
- Plan as a versioned artefact attached to a goal (`AgentPlan`)
- Plan → task graph expansion using the existing task graph and dependency
  admission (V0.5.3 / V0.5.4)
- Goal completes only when its graph completes; a failed node re-plans or blocks the goal
- Initial planner can be **rule/template-based**; model-based planning is optional and gated
- Model gateway (`anu-model-gateway`): API-first, Unix-socket only, budget,
  privacy classes, redaction, and validated structured output, as defined in
  [MODEL-STRATEGY.md](../MODEL-STRATEGY.md) and ADR-011. The planner must keep
  working without it.

Out of scope: free-form tool use (V0.6.2), memory-driven planning (V0.6.3).

## Design Notes

- Plans are data, not code: every planned step maps to an existing execution
  specification type.
- Re-planning creates a new plan version; old versions are kept for audit.
- The scheduler is unchanged: it still only wakes READY tasks.
- **Agent admission is separate from dependency readiness.** Graph READY means
  prerequisites finished. Agent READY means the task can become an
  `AgentGoal` (`goal_id`, non-empty `description`, integer `priority`).

**Progress**

- **Step 1: implemented.** `agent_admission(task)` next to `task_to_agent_goal`.
  The production WAKE handler blocks a task that cannot become an
  `AgentGoal` (`status=blocked`, `failure_class=contract`, `TASK_BLOCKED`
  event) and returns a structured failure instead of raising. One poison
  pending task no longer aborts the whole scheduler cycle (V0.6.0 live
  evidence finding). Tests: `test_agent_admission_v0_6_1.py`.

## Exit Criteria

- [ ] A goal-less (or otherwise ineligible) pending task is blocked alone;
      other READY tasks in the same cycle still run
- [ ] A single goal produces a multi-task graph that the production service executes in dependency order
- [ ] Goal status is derived from its task graph
- [ ] Failure of one node re-plans or blocks the goal with a recorded reason
