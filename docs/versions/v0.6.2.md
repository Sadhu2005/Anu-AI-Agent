## Goal

Give ANU **controlled capabilities** instead of unrestricted execution.

```text
Agent → capability request → policy → resource admission → tool → result
```

## Initial Capabilities

```text
filesystem.read     filesystem.write   (deferred; not in registry invoke yet)
python.test         python.compile
git.status          git.diff           (hardened host git only; F4)
research            browser            (disabled until V0.6.7)
```

Mapped today onto existing gateway commands / profiles.

## Capability Contract

Every capability declares:

| Field | Meaning |
|---|---|
| permission | Who/what may invoke it, in which projects |
| resource limit | Execution profile (RAM, CPU, timeout, output size) |
| input contract | Validated schema of arguments |
| output contract | Shape of a successful result |
| failure contract | Typed failure classes (feeds V0.6.0 retry classification) |
| audit record | What is written for every invocation |

## Design Notes

- Builds on the existing command gateway allow-list and execution profiles
  (`config/anu-command-gateway.yaml`, `config/anu-execution-profiles.yaml`):
  existing named commands become the first capabilities.
- Sandbox ops `python_test` / `python_compile` are in both YAML
  `allowed_commands` and gateway `COMMANDS`; startup fails on drift (F13).
- Capabilities are registered in config, not discovered dynamically.
- `research` and `browser` stay disabled until V0.6.7 approval exists
  (`downloads.enabled: false` today).
