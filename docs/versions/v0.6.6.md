# ANU V0.6.6 — Resource-aware Intelligence

| | |
|---|---|
| **Status** | Planned |

| **Depends on** | V0.6.0 |

## Goal

ANU chooses work based on machine conditions, not just a single NORMAL /
not-NORMAL gate.

```text
RAM low                 → don't start heavy task
temperature high        → WAIT
disk low                → DENY
one task already running → queue next task
```

## Scope

- **Single source of resource policy.** V0.5.9 aligned the values
  (60 / 65 °C, 50 GB, 3 attempts), but they still live in three files read by
  different components, and `config/anu-policy.yaml` is not read by code.
  Make one file authoritative and have Guardian, Governor and Task Engine
  read limits from it (including `MAX_ATTEMPTS`, currently hard-coded).
- **Temperature hysteresis:** resume only below `resume_celsius` (55 °C), so
  ANU does not flap between NORMAL and WARNING around 60 °C.
- Per-task resource estimate from its capabilities' execution profiles
- Admission decision per task: RUN, WAIT (with re-wake condition), DENY
- Heavy-workload thresholds (`heavy_workload_ram_threshold_mb: 1024`,
  `heavy_workload_cpu_threshold_percent: 60`) used in scheduling
- Production services on the Pi (e.g. existing Docker workloads) keep
  priority over ANU (`production.priority: highest`)

## Exit Criteria

- [ ] One resource policy file is authoritative and read by Guardian, Governor and Task Engine
- [ ] Hysteresis: after a WARNING, work resumes only below the resume temperature
- [ ] Heavy tasks are deferred under low RAM, and resumed automatically
- [ ] Temperature-based WAIT re-wakes when the Pi cools
