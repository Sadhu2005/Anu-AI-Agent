# ANU V0.6.7 — Human Approval Boundary

| | |
|---|---|
| **Status** | Planned |
| **Branch** | `v0.6.7-integration` |
| **Depends on** | V0.6.2 |

## Goal

ANU should not need humans for normal work, but risky operations stop and ask.

```text
AUTONOMOUS          when safe
HUMAN-IN-THE-LOOP   when risky
DENY                when unsafe
```

## Classification

| Situation | Decision |
|---|---|
| Normal file < 250 MB | Automatic |
| Large file (up to 2048 MB) | Approval |
| Dangerous operation | Approval |
| Unknown resource | Deny (existing `when_unknown_resource: deny`) |
| Major project mutation | Approval |
| Production-impacting action | Approval (existing `production_deployment_requires_approval`) |

## Scope

- Approval request record (what, why, risk, proposed change, expiry)
- Task enters WAITING with an approval wake condition (reuses V0.5.7 semantics)
- Approval channel (CLI first; notification channel later)
- Approved / rejected / expired outcomes, all audited

## Model gateway

The **`anu-model-gateway`** service is planned as a **separate release** after
V0.6.5 verification and this approval boundary — see
[MODEL-STRATEGY.md](../MODEL-STRATEGY.md) and [ROADMAP.md](../ROADMAP.md)
(review §8). V0.6.7 does not ship the gateway binary.

## Exit Criteria

- [ ] Risky actions never execute without a recorded approval
- [ ] Approved tasks resume from WAITING automatically
- [ ] Rejected or expired approvals end the task cleanly
