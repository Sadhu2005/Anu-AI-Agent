version, **no new major architecture** before V0.7.0.

```text

                                         ├── G1, G2, G3 closed with evidence
                                         ├── regression and negative tests
                                         ├── permission / systemd verification
                                         ├── sandbox verification
```

> **A known security gap is not closed because the code or configuration

## Security Gaps to Close

Copied verbatim from [SECURITY.md](../SECURITY.md) section 22.

| ID | Gap | Risk | Proposed fix |
|---|---|---|---|
| G1 | `/srv/anu/secrets` is a `ReadWritePath` for the whole agent process | Any agent code path can read **and modify** every secret, contrary to "only the component that needs it" | Make it read-only for the service (`ReadOnlyPaths`). Later, deliver secrets per capability (e.g. systemd `LoadCredential=`) |
| G2 | `/srv/anu/tests` is a `ReadWritePath`, owned by `anu-agent` | ANU could alter its own regression tests, weakening the verification it is judged by | Make tests root-owned and read-only to the service (follows from the root-owned checkout in WORKFLOW.md) |
| G3 | `/srv/anu/.git` is owned by `anu-agent` | Not writable by the service (`ProtectSystem=strict`), but the `anu-agent` user owns the repository history and hooks | Make it root-owned ([WORKFLOW.md](../WORKFLOW.md) section 25) |

### Required evidence per gap

Each gap is closed only when its **negative test** shows that the forbidden
action fails.

| ID | Fix | Negative test (must fail / must hold) |
|---|---|---|
| G1 | Move `secrets` from `ReadWritePaths` to `ReadOnlyPaths` in `deploy/systemd/anu-agent.service`, and in `config/anu-policy.yaml` writable paths | From inside the running service, writing to `/srv/anu/secrets` fails with `EROFS` (read-only file system). `systemctl show anu-agent -p ReadWritePaths` no longer lists it |
| G2 | `chown -R root:root /srv/anu/tests`; move `tests` from `ReadWritePaths` to `ReadOnlyPaths` | From inside the service, writing to `/srv/anu/tests` fails. As the `anu-agent` user, `touch /srv/anu/tests/x` fails with `EACCES`. The full suite still runs (`sudo -u anu-agent python3 -B …`, with no bytecode written) |
| G3 | `chown -R root:root /srv/anu/.git /srv/anu/.gitignore` after inspecting hooks; Pi git runs as root ([WORKFLOW.md](../WORKFLOW.md) section 12) | As the `anu-agent` user, writing to `.git` fails (e.g. `sudo -u anu-agent git -C /srv/anu commit --allow-empty -m probe` fails). `.git/hooks` has no non-sample hooks |

### How "from inside the service" is tested

Add a **boundary self-check** to `anu-runtime.py` at startup. Running inside
the real unit, it is the only test that sees the actual systemd sandbox:

- Every path that must be read-only (`bin`, `config`, `src`, `secrets`,
  `tests`): a probe write must fail.
- Every path that must be writable (`home`, `brain`, `workspace`, `sandbox`,
  `browser`, `logs`, `runtime`, `checkpoints`): a probe write must succeed and
  is removed.
- The result is recorded as an `agent_events` row (`BOUNDARY_CHECK`).
- **Fail closed:** if any boundary is wrong, the runtime keeps health
  checks running but never schedules autonomous work.

Tests: `test_boundary_self_check_v0_6_9.py` (logic, with temporary paths),
plus the production evidence: the `BOUNDARY_CHECK` event after deployment.
