## Goal

Give ANU a **replaceable intelligence provider** without giving the agent
general network access or rewriting the runtime.

```text
anu-agent (PrivateNetwork)
    │  Unix socket (later) / local client
    ▼
anu-model-gateway
    │  HTTPS or LAN HTTP
    ▼
OpenAI-compatible API
  ├── LM Studio on your PC (LAN)
  ├── OpenAI / other cloud
  └── Any server that speaks /v1/chat/completions
```

**Switching providers** = change config (`base_url`, `model`) and the API key
credential. Protocol stays the same. No code fork per vendor.

## Why after V0.7.0

V0.7.0 proved Goal → Plan → Execute → Verify → Remember with a **template**
planner. V0.7.1 adds the missing intelligence pipe so planning can use an LLM
when the gateway is healthy, and fall back to templates when it is not.

## Provider switch (operator rule)

| Knob | Where | Examples |
|---|---|---|
| `base_url` | `config/anu-model-gateway.yaml` | `http://192.168.1.50:1234/v1` (LM Studio), `https://api.openai.com/v1` |
| `model` | same YAML | `meta-llama-3.1-8b-instruct`, `gpt-4o-mini`, … |
| `api_key` | systemd `LoadCredential=` / env — **never** committed | LM Studio: any string or empty; OpenAI: real key |

See [MODEL-GATEWAY.md](../MODEL-GATEWAY.md).

## Exit Criteria

- [ ] Gateway can complete a chat against LM Studio on LAN
- [ ] Same binary works against a cloud OpenAI-compatible endpoint by config/key only
- [ ] Agent remains without general internet; only gateway has narrow network
- [ ] API key not in git / not in agent-writable secrets tree
- [ ] Template planner still works when gateway is down
- [ ] Portable tests + Pi evidence; tag `v0.7.1`

## Non-goals (this version)

- Running a large model on the Pi
- Giving `anu-agent` outbound HTTP
- Letting the model execute shell or bypass Safe Mutation
